# TrustLock — Architecture

## Overview

TrustLock is a decentralised escrow protocol. Users can lock ETH between a **buyer** and a **seller**, optionally nominating a neutral **arbiter** for dispute resolution. All fund custody and state transitions happen on-chain via a Solidity smart contract; the React frontend is a pure client-side dApp with no backend server.

## Smart Contract Layer

### `Escrow.sol`

Inherits from OpenZeppelin:
- `ReentrancyGuard` — protects ETH transfer functions from reentrancy attacks.
- `Ownable` — restricts admin functions (fee updates) to the platform owner.

**State machine:**

```
AWAITING_PAYMENT → AWAITING_DELIVERY → COMPLETE
                                      ↘ DISPUTED → COMPLETE (seller wins)
                                                  → REFUNDED (buyer wins)
                   ↘ CANCELLED
```

Each deal is uniquely identified by an auto-incrementing `uint256 dealId`.

## Frontend Layer

Built with:
- **React 18** — component tree and hooks-based state.
- **Vite 5** — bundler with HMR for development.
- **React Router v6** — client-side routing.
- **Ethers.js v6** — Ethereum interaction.

Data flow:

```
UI Component
    ↓ calls hook
useEscrow / useWallet
    ↓ calls service
escrowService / blockchain
    ↓ Ethers.js Contract call
    ↓ MetaMask signs & broadcasts
Ethereum node
```
